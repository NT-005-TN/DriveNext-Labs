# DriveNext — лабораторная работа №2

Самостоятельный Android-проект на Kotlin (минимальная версия Android 12), реализующий:

- выбор входа или регистрации;
- форму входа с проверкой email и видимостью пароля;
- регистрацию из трёх последовательных шагов;
- выбор дат через `MaterialDatePicker`;
- выбор фото профиля и документов через Activity Result API;
- валидацию обязательных полей и сохранение данных между шагами;
- экран успешной регистрации с очисткой стека навигации.

## Запуск

1. Откройте папку `DriveNextLab2` в Android Studio.
2. Дождитесь синхронизации Gradle.
3. Запустите приложение на эмуляторе или устройстве с Android 12+.

## Подключение Supabase

Проект: `owkzoimnjojfuoxzufnz`, API: `https://owkzoimnjojfuoxzufnz.supabase.co`.
Приложение обращается по HTTPS к Supabase Auth, PostgREST и Storage через
`SupabaseAuthRepository`. В коде только публичный publishable key; пароль базы,
service_role и Google client secret в приложение не включаются.

Поток вызовов: Activity → AuthViewModel → AuthUseCase → AuthRepository → Supabase.
Сетевые операции работают на Dispatchers.IO. ViewModel хранит состояние запроса,
экран блокирует повторную отправку и показывает progress bar. Ошибки отображаются
в диалоге; без интернета открывается NoConnection с возвратом к исходной форме.

### Данные

- Supabase Auth (`auth.users`): учётная запись, email, подтверждение email,
  защищённые сервером данные аутентификации и привязки провайдеров.
- `public.profiles`: UUID пользователя, фамилия, имя, отчество, дата рождения,
  пол, номер и дата выдачи удостоверения, пути к изображениям.
- Storage, приватный bucket `registration-documents`: файлы в папках UUID
  пользователя (`license`, `passport`, необязательный `avatar`). Лимит 10 МБ,
  JPEG/PNG/WebP. RLS разрешает доступ только владельцу.
- На устройстве: зашифрованные сессия и черновик в SharedPreferences
  `secure_auth`; ключ AES-GCM хранится в Android Keystore. Пароль в черновик
  на диске не записывается, после завершения процесса его нужно ввести снова.

Миграция `supabase/schema.sql` применена к проекту. Повторный запуск без
изменения имён уже созданных политик не предусмотрен: файл — начальная миграция.

### Проверка регистрации

1. Заполнить три шага, выбрать тестовые изображения, нажать «Далее».
2. Если включено подтверждение email (оно не отключалось), подтвердить адрес
   по письму Supabase. Вернуться в форму и повторно нажать «Далее».
3. Только после входа, загрузки фото и записи профиля открывается экран успеха.
   При сбое загрузки повторное нажатие повторяет upsert, а не создаёт новую запись.
4. Проверить Auth → Users, Table Editor → profiles, Storage → registration-documents.
5. Выйти, войти тем же email/паролем, перезапустить приложение для проверки сессии.

Ограничения стандартной почты Supabase (получатели и rate limit) могут потребовать
собственный SMTP. Ошибка отправки письма не считается успешной регистрацией.

### Google OAuth и восстановление пароля

Приложение реализует browser OAuth с PKCE и проверкой state.
В Supabase разрешён redirect `drivenextlab2://auth/callback?state=*`.
Для Google нужен Web application OAuth client с redirect URI:
`https://owkzoimnjojfuoxzufnz.supabase.co/auth/v1/callback`.
Client ID и Client Secret задаются только в Supabase → Authentication → Providers → Google.
Секрет не следует добавлять в Git или APK.
Без настроенного провайдера приложение показывает объяснение, а не имитирует вход.
Google-провайдер включён в проекте; отдельный Web OAuth client `DriveNext Lab2`
создан в Google Cloud CProject. Секрет введён владельцем только в Supabase.

«Забыли пароль?» отправляет письмо восстановления; ссылку нужно открыть на том же
устройстве, где начат запрос, после чего приложение предложит новый пароль.

## Статус проверки

Сборка, локальные тесты и четыре проверки на эмуляторе (шифрование, неверный пароль
на реальном Supabase, отклонение чужого OAuth callback, формирование Google PKCE
запроса с проверкой настроек реального сервера и отклонением чужого state) прошли.
Успешная регистрация с подтверждением почты, полный Google-вход и восстановление
пароля требуют проверки с аккаунтом владельца; прохождение пока не подтверждено.

Выход очищает локальные токены даже при недоступном сервере. В таком случае
серверный отзыв сессии не гарантирован — это локальный выход, а не отзыв всех
сессий аккаунта. Главный экран повторно проверяет сессию при открытии.
