# DriveNext — лабораторная работа №3

Накопительная версия: включает предыдущие лабораторные. Первый запуск проходит
через заставку и онбординг; после завершения онбординга открывается авторизация.
Завершённый онбординг не повторяется до очистки данных приложения.
Общие исправления входа, календаря и навигации перенесены в последующие лабы.

Отдельный проект Android 12+, Kotlin, ViewBinding, ViewModel, корутины.
Открывайте эту папку в Android Studio. JDK 21, Android SDK 35.
Приложение на устройстве называется «DriveNext ЛР 3».

## Реализация

- Настоящая авторизация Supabase: email/пароль, Google OAuth с PKCE, обновление сессии, выход, восстановление пароля.
- Три шага регистрации: серверная учётная запись, приватные фотографии, профиль.
- Каталог и поиск через PostgREST; результаты не подменяются локальным списком.
- Каталог и поиск загружаются страницами по 3 машины через PostgREST `offset`/`limit`; следующая страница подгружается при прокрутке.
- Поиск живой: часть слова сразу фильтрует текущий список; задержка 300 мс не даёт отправлять лишний запрос на каждую быстро введённую букву.
- Для пяти учебных машин в APK добавлены фотографии-резервы; фото из Supabase Storage имеет приоритет.
- Профиль и смена аватара сохраняются на сервере. Для аренды нужны имя, фамилия и удостоверение.
- Кнопки деталей, избранного, бронирования и списка броней открывают экран-заглушку: функции относятся к ЛР4.
- Добавление автомобиля открывает экран-заглушку с указанием ЛР5.
- Нет Toast-заглушек Google, demo_token и искусственных задержек загрузки.
- Заглушки имеют видимую кнопку «Назад» и прямо объясняют, в какой лабе появляется функция.

Остальные запросы идут через HTTP-клиент SDK; PKCE/state и зашифрованный

4. Google Web client использует общий серверный callback `https://owkzoimnjojfuoxzufnz.supabase.co/auth/v1/callback`.

RLS: каталог читают вошедшие пользователи; изменять машину может владелец.
Бронирования видит только создавший пользователь. Создание и отмена выполняются RPC.
Цена вычисляется на сервере, пересекающиеся аренды блокируются транзакционной блокировкой.
Повтор одного запроса не создаёт вторую бронь.

Время выбирается через MaterialTimePicker в формате ЧЧ:ММ, сохраняется при
пересоздании экрана и показывается в списке/деталях бронирования.
Это местное время получения автомобиля, без пересчёта часового пояса.
Тариф остаётся посуточным. У старых записей с NULL показано «время не указано».
Пустое время, 24:00 и секунды сервер отклоняет; повтор UUID с другим временем
не изменяет уже оформленную бронь.

Учебные тарифы новой машины: 3000 ₽/день, страховка 500 ₽/день, депозит 10000 ₽.
Срок считается включительно (аренда с 9 по 11 число — три дня); депозит показывается отдельно от суммы аренды и страховки.
Тарифы заданы в миграции и показаны пользователю на экране добавления машины.

## Проверка

`./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug`
`./gradlew :app:connectedDebugAndroidTest` — требует эмулятор с интернетом.

Автотесты не заменяют полный вход Google и подтверждение email.
Тест Google проверяет реальный HTTP 302 на accounts.google.com; это не полный вход.
Дополнительно проверены формат времени, старые записи без времени и серверная
идемпотентность времени; серверные тестовые записи откатились через ROLLBACK.
На реальном сервере выполнены транзакционные тесты с ROLLBACK: расчёт суммы, повтор запроса, конфликт дат, отмена, изоляция профилей/броней, приватность черновика, публикация с фото и запрет чужих изменений/фотографий. Тестовые учётные записи без паролей и все их записи откатились; они не являются аккаунтами для входа.
Полный пользовательский проход через Google/email, загрузка настоящего файла через приложение и визуальная приёмка после входа ещё требуют завершения. Успешная сборка и SQL-тесты не заменяют эту проверку.
Для демонстрации использовать только вымышленные анкеты и тестовые изображения.
